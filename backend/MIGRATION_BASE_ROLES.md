# Миграция базовых ролей

## Описание

Эта миграция добавляет таблицу `base_roles` для хранения истории базовых ролей пользователей с возможностью указания срока действия, аналогично таблице `platform_roles` для BF-ролей.

## Шаги для применения миграции

### 1. Применить миграцию базы данных

```bash
cd backend
alembic upgrade head
```

Это создаст таблицу `base_roles` в базе данных.

### 2. Мигрировать существующие данные (опционально)

Если у вас уже есть пользователи в базе данных, выполните скрипт для создания записей `base_roles` на основе их текущих ролей:

```bash
cd backend
python migrate_base_roles.py
```

Этот скрипт:
- Создаст записи `base_roles` для всех пользователей на основе их текущей роли в таблице `users`
- Установит `granted_at` равным `created_at` пользователя (или текущей дате)
- Установит `expires_at` в `NULL` (бессрочно)
- Пропустит пользователей, у которых уже есть записи `base_roles`

### 3. Проверка

После миграции проверьте, что:
- Таблица `base_roles` создана в базе данных
- Записи созданы для всех пользователей (если выполняли шаг 2)
- API endpoints работают корректно

## Откат миграции (если необходимо)

```bash
cd backend
alembic downgrade -1
```

Это удалит таблицу `base_roles` и все данные в ней.

## Структура таблицы base_roles

- `id` - первичный ключ
- `user_id` - ID пользователя (FK на users.id)
- `role_name` - название роли (owner, admin, developer и т.д.)
- `granted_by` - ID пользователя, который выдал роль (FK на users.id)
- `granted_at` - дата и время назначения роли
- `expires_at` - дата и время истечения роли (NULL = бессрочно)
- `is_active` - активна ли роль
- `notes` - заметки о роли

## API Endpoints

После миграции будут доступны следующие endpoints:

- `POST /api/platform-admin/base-roles` - назначить базовую роль с сроком действия
- `PATCH /api/platform-admin/base-roles/{role_id}` - обновить базовую роль
- `DELETE /api/platform-admin/base-roles/{role_id}` - удалить базовую роль
