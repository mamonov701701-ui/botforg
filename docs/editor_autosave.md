# Автосохранение черновиков сценариев

## Обзор

Редактор сценариев поддерживает автосохранение черновиков (draft) с индикатором состояния и защитой от потери данных.

## Функциональность

### 1. Автосохранение

- **Механизм:** debounce по изменениям сценария
- **Задержка:** ~5 секунд после последнего изменения (`updateCurrentScenario`)
- **Условие:** сохраняется только при наличии несохранённых изменений (`isDirty`)
- **API:** используется существующий `PUT /scenarios/{id}` для сохранения draft
- **Проверка перед сохранением:** не выполняется, если уже идёт сохранение (`isSaving`)

### 2. Индикатор состояния

В верхней панели редактора отображается статус:

| Статус | Описание |
|--------|----------|
| **Сохранено** | Все изменения сохранены |
| **Сохранение...** | Идёт процесс сохранения |
| **Ошибка сохранения** | Произошла ошибка (подсказка с текстом ошибки) |

Индикатор виден только при редактировании и наличии прав `scenario_edit`.

### 3. Защита от потери данных

#### beforeunload

При попытке закрыть вкладку или перезагрузить страницу, если есть несохранённые изменения, показывается стандартное предупреждение браузера.

#### localStorage-резервная копия

- При изменении сценария draft сохраняется в `localStorage` (debounce 2 сек)
- Ключ: `scenario_draft_{botId}_{scenarioId}`
- При повторном открытии редактора с тем же сценарием предлагается восстановить несохранённые изменения
- Резервная копия очищается при успешном сохранении или при отказе пользователя от восстановления

### 4. Ограничения

- **Demo-режим:** автосохранение отключено (`isReadOnly`)
- **Роли без `scenario_edit`:** автосохранение не выполняется
- **Без выбранного сценария:** индикатор и автосохранение не активны

## Реализация

### Frontend

- **scenarioStore.ts:** логика автосохранения, `saveStatus`, localStorage backup
- **EditorControls.tsx:** индикатор, beforeunload, restore prompt, условия включения автосохранения

### Backend

Endpoint `PUT /scenarios/{id}` идемпотентен: повторные вызовы с тем же содержимым не создают побочных эффектов. Каждый запрос независим, race-condition не возникает. Debounce реализован на клиенте (задержка ~5 сек после последнего изменения).
