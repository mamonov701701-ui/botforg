# Режим минимального хранения персональных данных (152-ФЗ)

## Назначение

Режим позволяет минимизировать объём хранимых персональных данных: по умолчанию тексты сообщений и привязка к пользователю не сохраняются, хранятся только агрегированные события. Обработка сообщений и вызовы AI выполняются только в памяти.

## Поведение

- **Сообщения (таблица `messages`)**: при флаге бота `store_messages = false` (по умолчанию) при создании сообщения в БД записываются пустой `content`, `user_id = null`, `language = null`. При `store_messages = true` сохраняются полные данные.
- **События (таблица `events`)**: при минимальном режиме (бот с `store_messages = false`) в эндпоинт `POST /analytics/event` передаётся `bot_id`; в БД сохраняются только поля: `event_type`, `event_name`, `bot_id`, `channel`, `chat_hash`, `node_id`, `created_at`. Поля `payload`, `user_id`, `session_id`, `ip_address`, `user_agent` не сохраняются (пустые/null).
- **Автоочистка**: ежедневная задача удаляет сообщения и события старше срока `message_retention_days` по каждому боту.
- **PII перед LLM**: перед любыми вызовами LLM применяется модуль `pii_scrubber` (маскирование телефонов, email, username, числовых ID).

## Настройки бота

| Поле | По умолчанию | Описание |
|------|--------------|----------|
| `store_messages` | `false` | Хранить тексты сообщений и привязку к пользователю |
| `message_retention_days` | `30` | Срок хранения сообщений и событий (дней) |

Задаются через `PATCH /bots/{bot_id}` (тело: `store_messages`, `message_retention_days`). В ответах `GET /bots`, `GET /bots/{id}` возвращаются эти поля.

## Агрегированные события

Поля события в режиме минимального хранения:

- `event_type` — тип события (например, `bot_message`, `scenario_run`)
- `event_name` — название события
- `channel` — канал (telegram, web и т.д.)
- `chat_hash` — хеш чата (без ПДн)
- `node_id` — узел сценария
- `created_at` — метка времени

Передача при вызове `POST /analytics/event`: параметры `bot_id`, `channel`, `chat_hash` или `chat_id` (опционально). При передаче `chat_id` сервер вычисляет `chat_hash` по HMAC; `chat_id` в БД и логах не сохраняется. При переданном `bot_id` и `store_messages = false` у бота сохраняются только эти агрегаты.

**Экспорт данных (/privacy/export):** при минимальном хранении в выгрузку попадают только сообщения с непустым контентом и привязкой к пользователю; если контент не хранился — список сообщений пуст или без контента, в ответе присутствуют поля `messages_stored` и пояснение в `note`. События в экспорте отдаются только в виде агрегатов (event_type, event_name, bot_id, channel, chat_hash, node_id, created_at) по событиям пользователя и по ботам владельца; payload, user_id, ip, user_agent, session_id в экспорт не включаются.
