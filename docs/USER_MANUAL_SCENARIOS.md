# Руководство пользователя: сценарии и блоки

> Для пользователей без технической подготовки.  
> Здесь описаны все актуальные блоки редактора и как ими пользоваться на практике.

## С чего начать

1. Откройте бота и перейдите в `Редактор`.
2. Нажмите `Добавить блок`.
3. Соберите цепочку блоков слева направо.
4. После изменений нажмите `Сохранить`.
5. Проверьте сценарий в `Предпросмотре`.

## Как читать схему

- Стрелка между блоками = куда пойдет сценарий дальше.
- Если у блока 2 выхода (`Да/Нет`, `Успех/Ошибка`) — подключайте обе ветки.
- Если у блока нет исходящей связи — сценарий остановится.

## Блоки редактора (простым языком)

### 1) `Начало`
- Точка входа сценария.
- Должен быть в каждом сценарии.
- От него обязательно нужна исходящая связь.

### 2) `Сообщение`
- Отправляет пользователю текст.
- Можно добавить кнопки и медиа.
- Если есть кнопки — сценарий ждет нажатие.
- Если кнопок нет — переходит дальше автоматически.

Когда использовать:
- приветствие;
- меню;
- пояснение перед вопросом.

### 3) `Ввод`
- Задает вопрос и ждет ответ пользователя.
- Ответ сохраняется и доступен дальше в сценарии.
- Есть валидация (тип, длина, обязательность и т.д.).

Важно:
- обязательно подключите выход `Успех`;
- при отдельной обработке ошибки подключите и ветку `Ошибка`.

### 4) `Условие`
- Проверяет данные и отправляет пользователя по ветке `Да` или `Нет`.
- Для режима `Тег` сравнение идет по тегам пользователя.
- Для других режимов сравнение идет по выбранному источнику данных.

Важно:
- подключайте обе ветки (`Да` и `Нет`);
- у одного выхода должна быть только одна связь;
- если сравниваете тег — указывайте нужный тег в поле `Какой тег`.

### 5) `Данные пользователя` (бывш. «Действие»)
- Меняет данные пользователя:
  - теги (`добавить` / `удалить`);
  - статус (`установить` / `очистить`);
  - поле пользователя (`записать` / `очистить`).
- Можно добавить короткое сообщение в чат после действия.

Важно:
- выполняется одно действие за блок;
- после блока должна быть исходящая связь.

### 6) `Переменная`
- Записывает значение в переменную сценария.
- Используется для служебной логики внутри сценария.

### 7) `Ожидание`
- Делает паузу перед следующим шагом.
- В предпросмотре длинные задержки ограничены, чтобы тест не зависал.

### 8) `Перейти в сценарий`
- Переключает выполнение в другой сценарий.
- После перехода выполнение продолжается уже в целевом сценарии.
- Состояние сохраняется:
  - переменные;
  - теги;
  - статус;
  - поля пользователя;
  - последний ввод;
  - история сообщений.

Важно:
- целевой сценарий должен существовать;
- в целевом сценарии должен быть `Начало`, иначе будет понятная ошибка в предпросмотре.

## Что показывает предпросмотр

Предпросмотр показывает:
- диалог как у пользователя;
- переходы между блоками;
- переходы между сценариями;
- причину остановки (если сценарий не может идти дальше).

Предпросмотр не делает:
- реальную отправку сообщений в канал;
- запись данных в CRM как у реального пользователя.

## Понятные причины остановки в предпросмотре

Вы увидите явные причины, например:
- нет исходящего ребра у блока;
- не найден целевой сценарий для перехода;
- в целевом сценарии нет стартового блока;
- блок ждет ввод пользователя;
- возможно зацикливание сценария (достигнут лимит шагов).

## Рекомендуемый шаблон сценария

Минимально надежная структура:
1. `Начало`
2. `Сообщение` (что происходит)
3. `Ввод` (если нужен ответ)
4. `Условие` (если нужна логика ветвления)
5. `Данные пользователя` (если нужно изменить тег/статус/поле)
6. `Сообщение` (подтверждение)

## Частые ошибки и быстрые решения

1. Сценарий «завис»
- Проверьте, есть ли исходящая связь у текущего блока.

2. Ветвление идет не туда
- Проверьте, что для `Условие` заполнен правильный источник данных и подключены обе ветки.

3. Переход в другой сценарий не срабатывает
- Проверьте `Куда перейти` и наличие блока `Начало` в целевом сценарии.

4. Данные пользователя не меняются
- Проверьте настройки блока `Данные пользователя` и сохранение сценария после изменений.

## Короткий чек-лист перед публикацией

- [ ] У каждого блока есть нужные исходящие связи.
- [ ] У `Условие` настроены и подключены `Да/Нет`.
- [ ] У `Ввод` подключен `Успех` (и `Ошибка`, если используете).
- [ ] У `Перейти в сценарий` указан существующий сценарий с блоком `Начало`.
- [ ] Сценарий проходит в `Предпросмотре` до конца без неясных остановок.
