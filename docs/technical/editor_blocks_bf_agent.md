# Блоки редактора: справка для BF-агента

Текст для настройки сценариев и разбора ошибок. Пояснения на русском. Имена полей в таблицах и строковые литералы в сохранённом сценарии приведены в том виде, в каком их записывает редактор и читает код (латинские ключи — часть контракта данных).

Поведение **предпросмотра** снято с исполнителя шагов в исходниках приложения (модуль симулятора сценария, файл `scenarioRunner.ts`). Поведение **рабочего запуска** на сервере может отличаться; переход между сценариями на сервере описан в службе сценария (`scenario_runtime.py` в каталоге серверной части).

Ключи полей в данных узла совпадают с именем поля в каталоге блоков (`editor_blocks.json` в данных серверной части); в узле графа они лежат в объекте настроек.

---

## Общие зависимости предпросмотра

- Граф текущего сценария: узлы и рёбра из редактора.
- Для блока «Перейти в сценарий»: в состоянии симулятора должны быть карта графов по номеру сценария и подписи сценариев; целевой сценарий входит в эту поставку.
- Для блока «Выбор» (`condition`): исходящие ребра помечаются как ветка «Совпало» или «Не совпало» (`edge.data.conditionBranch`: `true` / `false`, либо handles `condition_yes` / `condition_no` и fallback по порядку id). Предпросмотр читает настройки узла (`conditionSourceType`, `variable`, `conditionKey`, `operator`, `value`) и выбирает целевой узел по результату сравнения (см. раздел «Выбор» ниже).

## Начало (`start`)

**Назначение.** Точка входа в граф; при первом шаге предпросмотра выбирается стартовый узел встроенной логикой поиска старта в симуляторе.

**Поля.**

| Ключ | Тип | Обязательность |
|------|-----|----------------|
| `autoStart` | логический | нет |

**Поведение в предпросмотре.** Поле `autoStart` не читается. Если у узла есть кнопки — показывается сообщение, ожидание выбора. Если кнопок нет: при непустом показываемом тексте или заголовке — сообщение в историю, затем переход по первому исходящему ребру; при пустом тексте и без кнопок пузырь не добавляется, сразу переход по первому ребру. Нет исходящего ребра — служебная ошибка в истории.

**Ограничения.** Один старт выбирается логикой поиска узла старта; при нескольких кандидатах приоритет у узла с признаком старта в данных.

**Зависимости.** Исходящее ребро для продолжения цепочки (кроме случая только кнопок).

**Предпросмотр.** Текст и кнопки собираются так же, как у сообщения, из настроек узла.

**Ошибки.** «В сценарии нет перехода из стартового блока…» при отсутствии следующего узла после разрешения перехода.

**Пример настроек.** `autoStart`: истина (для шаблона); текст пуст, одно ребро к узлу «Сообщение».

---

## Сообщение (`message`)

**Назначение.** Исходящее сообщение бота: текст, один тип вложений, кнопки, режим оформления текста.

**Поля.**

| Ключ | Тип | Обязательность |
|------|-----|----------------|
| `text` | многострочный текст | да (в каталоге) |
| `buttons` | список кнопок | нет |
| `mediaType` | перечисление | нет |
| `mediaList` | список медиа | нет |
| `parseMode` | перечисление | нет |
| `disablePreview` | логический | нет |
| `saveLastMessageId` | логический | нет |

Допустимые значения перечисления оформления текста задаёт каталог блоков в репозитории; в интерфейсе подписи вариантов на русском.

**Поведение в предпросмотре.** Собирается сообщение для чата. Есть кнопки — после показа ожидание действия пользователя. Нет кнопок — переход по первому исходящему ребру; без ребра — ошибка.

**Ограничения.** Один `mediaType` на блок; список вложений того же типа. Поля канала (`disablePreview`, `saveLastMessageId`) сохраняются в шаблон; предпросмотр не отправляет сообщения во внешний канал.

**Зависимости.** При отсутствии кнопок — исходящее ребро.

**Предпросмотр.** Разметка отображается виджетом чата. Кнопка с переходом ведёт по связанному ребру; открытие ссылки — переход браузера по полному адресу из действия кнопки.

**Ошибки.** Нет перехода из сообщения без кнопок.

**Пример.** Текст приветствия, две кнопки с разными исходящими рёбрами.

## Ввод (`input`)

**Назначение.** Вопрос пользователю и сохранение ответа в переменную.

**Поля.**

| Ключ | Тип | Обязательность |
|------|-----|----------------|
| `text` | многострочный текст | да |
| `variableName` | строка | да |

**Поведение в предпросмотре.** Сообщение с текстом вопроса, ожидание ввода строки. После ввода значение кладётся в словарь переменных под именем из настроек и в последний ответ пользователя; переход по первому исходящему ребру.

**Ограничения.** Формат ввода в предпросмотре не проверяется.

**Зависимости.** Исходящее ребро после ввода.

**Предпросмотр.** Строка из поля ввода интерфейса симулятора попадает в историю как сообщение пользователя (не кнопочный выбор).

**Ошибки.** Отсутствие ребра обрабатывается при попытке перехода как у других блоков.

**Пример.** Текст вопроса задан; поле имени переменной заполнено; одно исходящее ребро после ввода.

## Ожидание (`wait`)

**Назначение.** Задержка перед следующим узлом.

**Поля.**

| Ключ | Тип | Обязательность |
|------|-----|----------------|
| `duration` | длительность или число | да |
| `canSkip` | логический | нет |

**Поведение в предпросмотре.** Длительность задаётся числом секунд либо объектом с количеством и строкой единицы; строка единицы совпадает с теми значениями, которые записывает поле типа «длительность» и принимает парсер в исходнике симулятора. Итог в миллисекундах ограничен сверху константой предпросмотра (45 с), снизу не меньше 400 мс. После таймера в историю добавляется служебная строка о прохождении паузы, переход по первому ребру. Поле «можно пропустить» (`canSkip`) не читается.

**Ограничения.** Некорректный объект даёт запасное значение по коду парсера; полностью неизвестное значение даёт 1200 мс.

**Зависимости.** Исходящее ребро после паузы.

**Предпросмотр.** Длительность паузы передаётся интерфейсу симулятора; по окончании отсчёта вызывается процедура завершения шага ожидания в симуляторе.

**Ошибки.** Нет перехода после «Ожидание».

**Пример.** Длительность задана через форму «длительность» редактора; одно исходящее ребро после паузы.

## Выбор (`condition`)

**Назначение.** Направляет сценарий по двум исходящим веткам в интерфейсе: «Совпало» и «Не совпало» (тип узла в данных по-прежнему `condition`).

**Поля.**

| Ключ | Тип | Обязательность |
|------|-----|----------------|
| `conditionSourceType` | строка | задаётся в форме редактора (источник сравниваемого значения) |
| `variable` | строка | да в каталоге; смысл зависит от источника |
| `conditionKey` | строка | нет |
| `operator` | перечисление | да в каталоге |
| `value` | строка | нет |

**Поведение в предпросмотре.** Для пары исходящих рёбер вызывается разрешение веток «Совпало» / «Не совпало» (`resolveConditionYesNoEdges`: `edge.data.conditionBranch` `true`/`false`, иначе handles `condition_yes`/`condition_no`, иначе первое и второе ребро по порядку id). Значение для сравнения зависит от `conditionSourceType`: для тегов — отдельная ветка оценки по списку тегов в переменных предпросмотра; иначе — `evaluateConditionSettings` над фактическим значением из `variables` и/или последнего ввода (ключ `conditionKey` при наличии, иначе `variable`). При истинном результате — переход по ветке «Совпало», иначе — «Не совпало». Более двух исходящих связей: используются только две, остальные игнорируются (служебное сообщение в истории предпросмотра).

**Ограничения.** Сценарий должен содержать корректную пару веток; данные для выбранного источника должны быть доступны к моменту шага (см. пользовательскую справку в `blockGuideRu.ts`).

**Зависимости.** Одна или две исходящие связи от узла (при одной связи симулятор предупреждает, что один и тот же переход используется для обоих вариантов).

**Предпросмотр.** Без пузыря сообщения пользователю; возможны служебные строки в истории при ошибках или предупреждениях.

**Ошибки.** Нет исходящих связей; не удалось определить следующий узел после шага «Выбор».

**Пример.** Заданы источник и проверяемое значение в настройках; от узла выходят две связи с ветками «Совпало» и «Не совпало».

## Перейти в сценарий (`go_to_scenario`)

**Назначение.** Смена активного графа на граф другого сценария.

**Поля.**

| Ключ | Тип | Обязательность |
|------|-----|----------------|
| `targetScenarioId` | выбор сценария | да |
| `startMode` | перечисление | да |
| `targetNodeId` | выбор узла | при `startMode` = вход с шага |
| `preserveContext` | логический | нет |

**Поведение в предпросмотре.** В историю добавляется служебное сообщение о переходе. Если целевой граф отсутствует или пуст — ошибка и переход по запасному ребру из текущего узла, если оно есть. Иначе граф заменяется нормализованным графом цели, номер активного сценария обновляется, текущий узел — выбранный шаг или старт целевого графа по той же логике поиска старта, что и при обычном входе. Поле «сохранить контекст» (`preserveContext`) **не** читается: переменные не очищаются.

**Ограничения.** Идентификатор сценария должен разрешаться в число и иметь запись в карте графов, подготовленной для симулятора.

**Зависимости.** Поставка графов других сценариев в состояние симулятора; при ошибке — опциональное запасное ребро.

**Предпросмотр.** После смены графа следующий такт обработки идёт с нового текущего узла.

**Ошибки.** «Не найден целевой сценарий…»; «Целевой сценарий пуст…».

**Пример.** Целевой сценарий выбран в поле перехода; режим старта — с начала целевого графа.

**Сервер.** В службе сценария на сервере поле `preserveContext` участвует в переносе переменных при рабочем исполнении.

## Переменная (`variable`)

**Назначение.** Запись в словарь переменных без сообщения пользователю.

**Поля.**

| Ключ | Тип | Обязательность |
|------|-----|----------------|
| `name` | строка | да |
| `value` | строка | нет |
| `type` | перечисление | нет |
| `scope` | перечисление | нет |

**Поведение в предпросмотре.** Если имя переменной пусто, запись не выполняется. Если значение совпадает с литералом подстановки последнего ввода из подсказки редактора к полю «значение» (тот же литерал, что проверяется в коде симулятора), в переменную пишется последний ответ пользователя. Иначе в переменную пишется строка из настроек. Переход по первому исходящему ребру.

**Ограничения.** Тип и область видимости в предпросмотре не меняют хранение: один общий словарь переменных шага.

**Зависимости.** Исходящее ребро.

**Предпросмотр.** Новый пузырь бота не добавляется.

**Ошибки.** Нет перехода после блока.

**Пример.** Имя переменной задано; значение — подстановка последнего ответа из подсказки редактора; исходящее ребро к следующему узлу.

## Действие (`action`)

**Назначение.** Необязательное короткое сообщение в чат и необязательная запись переменной, затем переход.

**Поля.**

| Ключ | Тип | Обязательность |
|------|-----|----------------|
| `text` | многострочный текст | нет |
| `setVariable` | строка | нет |
| `value` | строка | нет |

**Поведение в предпросмотре.** Если задано непустое имя переменной для записи, в переменную записывается значение из настроек, с подстановкой последнего ввода по тому же правилу, что в блоке «переменная». Если после обрезки пробелов текст для чата не пуст, в историю добавляется сообщение бота; в метаданных сообщения симулятор помечает шаг как действие. Переход по первому исходящему ребру.

**Ограничения.** Нет кнопок и медиа в этом блоке в предпросмотре.

**Зависимости.** Исходящее ребро.

**Предпросмотр.** Сообщения с меткой вида «действие».

**Ошибки.** Нет перехода после блока.

**Пример.** В чат выводится короткая фраза «сохранено»; переменная состояния получает значение «готово»; затем переход по ребру.
