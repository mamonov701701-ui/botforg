# Блок «Перейти в сценарий» — Полная документация

## 1. Описание для обычного пользователя

### Что делает этот блок

**Простыми словами:**

Блок «Перейти в сценарий» позволяет продолжить диалог в другом сценарии.

**Например:**
- Пользователь прошёл оплату → дальше его должен вести отдельный сценарий "Доступ к курсу"

То есть это **"мостик"** между сценариями:
- **откуда:** текущая ветка
- **куда:** другой сценарий (или конкретный шаг внутри него)

---

### Когда его использовать

**Типичные случаи:**

#### 1. После оплаты
Сценарий "Оплата" → успешная ветка → **Переход в сценарий "Доступ к курсу"**

#### 2. Разделение логики по смыслу
Сценарий "Приветствие" → в конце:
- "Перейти в сценарий "Заказ"
- или "Перейти в сценарий "Поддержка"

#### 3. Переход к большому отдельному процессу
Например, из любого места можно перевести пользователя в:
- Сценарий "Онбординг"
- Сценарий "Анкета"
- Сценарий "Смена тарифа"

---

### Как найти блок в редакторе

1. Открываешь **библиотеку блоков** (кнопка "Добавить блок")
2. Выбираешь категорию: **"Системные"**
3. Ищешь блок: **"Перейти в сценарий"**
4. Иконка: **↪️** (поворотная стрелка)
5. Перетаскиваешь блок на схему и соединяешь его в конце нужной ветки

---

## Настройки блока (понятно и по-человечески)

Когда блок выделен, в правой панели доступны следующие поля:

### 1. **Куда перейти?** ⭐ (обязательное)

> _В коде:_ `targetScenarioId`, тип `scenario_select`

**Что это:**
- Выпадающий список всех сценариев вашего бота
- Показываются названия сценариев (например: "Приветствие", "Оформление заказа", "Поддержка", "Доступ к курсу")

**Специальная опция:**
- В списке есть пункт: **"+ Создать новый сценарий"**
- Если его выбрать:
  - Открывается стандартное окно создания сценария
  - После создания новый сценарий сразу подставляется в этот блок

**Подсказка для пользователя:**
> «Выберите сценарий, который должен продолжить диалог на этом шаге»

---

### 2. **С какого места начать?** ⭐ (обязательное)

> _В коде:_ `startMode`, тип `select`

**Варианты:**

#### ✅ "С начала сценария" (рекомендуется)
- Самый простой и основной вариант
- Новый сценарий запускается с его блока **"Начало"** (как будто пользователь только что в него зашёл)
- **Рекомендованный режим для 99% случаев**

#### 🔧 "С конкретного шага" (расширенная настройка)
- Для продвинутых сценариев
- Позволяет начать **не с самого начала**, а с определённого блока внутри этого сценария
- При выборе этого режима появляется дополнительное поле (см. ниже)

**Подсказка для пользователя:**
> «Будет запущен выбранный сценарий так, как будто пользователь вошёл в него с самого начала»

---

### 3. **Конкретный шаг** (расширенные настройки)

> _В коде:_ `targetNodeId`, тип `node_select`  
> _Показывается только при:_ `startMode = "from_step"`

**Что это:**
- Выпадающий список шагов (блоков) внутри выбранного сценария
- Для пользователя отображаются названия блоков, например:
  - "Шаг 1. Спросить имя"
  - "Шаг 2. Спросить email"
  - "Подтверждение заказа"
  - "Выбор тарифа"

**Подсказка для пользователя:**
> «Можно начать не с начала, а с конкретного шага внутри сценария (для продвинутых сценариев)»

---

### 4. **Сохранить контекст** ✅ (включено по умолчанию)

> _В коде:_ `preserveContext`, тип `boolean`, по умолчанию: `true`

**Подпись в интерфейсе:**
"Сохранить контекст" или "Передать переменные и данные пользователя в новый сценарий"

**Смысл:**

#### ✅ Если включено (по умолчанию):
- Всё, что уже было собрано в диалоге (имя, email, ответы, суммы, переменные) **передаётся** в новый сценарий
- Новый сценарий может использовать эти данные:
  ```
  «Здравствуйте, {{имя}}! Ваша оплата на {{сумма}} прошла успешно…»
  ```

#### ❌ Если выключено:
- Новый сценарий стартует как **"чистый лист"** — без старых переменных
- Полезно только в особых случаях, когда нужна полная изоляция

**Рекомендация:**
> «Оставьте включённым, если хотите использовать уже собранные данные в новом сценарии»

---

## Как использовать: пошаговая инструкция

### Пример задачи:
У вас есть сценарий **"Оплата"**, и после успешной оплаты нужно привести пользователя в сценарий **"Доступ к курсу"**.

### Шаги:

1. **Найдите место перехода**
   - В сценарии "Оплата" находите ветку успеха (например, выход из блока оплаты `success`)

2. **Добавьте блок**
   - В конец этой ветки перетащите блок **"Перейти в сценарий"**

3. **Настройте переход**
   - **Куда перейти?** → выбираете **"Доступ к курсу"**
   - **Как запускать сценарий?** → оставляете **"С начала сценария"**
   - **Сохранить контекст** → оставляете **включённым** ✅

4. **Сохраните сценарий**
   - Нажмите кнопку "Сохранить" в верхней панели

5. **Готово!**
   - Теперь, когда пользователь дойдёт до успеха в "Оплате", он автоматически продолжит диалог уже в сценарии "Доступ к курсу"

## Типичные ошибки и подсказки

### ❌ Ошибка 1: Не выбран сценарий в поле "Куда перейти?"
**Решение:**
- Выберите сценарий из списка
- Или создайте новый через опцию "+ Создать новый сценарий"

**Валидация покажет:**
> «Выберите сценарий, в который нужно перейти»

---

### ❌ Ошибка 2: Выбран режим "С конкретного шага", но шаг не выбран
**Решение:**
- Укажите конкретный шаг в выпадающем списке
- Или переключитесь обратно на "С начала сценария"

**Валидация покажет:**
> «Укажите, с какого шага начать сценарий, или переключитесь на запуск с начала»

---

### ⚠️ Ошибка 3: Целевой сценарий был удалён
**Что произойдёт:**
- В настройках блока появится предупреждение: **"Сценарий не найден (возможно, удалён)"**
- Блок будет подсвечен как проблемный (с иконкой ⚠️)
- В редакторе: предупреждение, что ссылка устарела

**Решение:**
- Выберите другой существующий сценарий
- Или создайте новый

---

## Советы и лучшие практики

### 💡 Совет 1: Используйте осмысленные названия сценариев
**Плохо:**
- "Сценарий 1"
- "Новый сценарий"
- "Test"

**Хорошо:**
- "Приветствие"
- "Оформление заказа"
- "Доступ к курсу после оплаты"
- "Поддержка — часто задаваемые вопросы"

---

### 💡 Совет 2: Начинайте с режима "С начала сценария"
- Это самый простой и понятный способ
- Режим "С конкретного шага" используйте только когда действительно нужно

---

### 💡 Совет 3: Сохраняйте контекст по умолчанию
- В большинстве случаев вам нужно сохранять собранные данные
- Отключайте только если точно понимаете зачем

---

### 💡 Совет 4: Документируйте сложные переходы
- Если у вас много переходов между сценариями
- Добавляйте комментарии в описание блоков
- Используйте понятные названия для блоков в сценариях

### 3. targetNodeId

```json
{
  "name": "targetNodeId",

  "label": "Конкретный шаг",
```

**Реализация:**

- API возвращает:
  ```typescript

    id: string;           // ID блока
    title: string;        // Название блока
    block_type: string;   // Тип блока (start, message, etc.)
    icon?: string;        // Иконка блока
  }
  ```

**Валидация:**
- При `startMode === "from_step"`: обязательно для заполнения
- Проверка существования блока в целевом сценарии

## Runtime исполнение

### ScenarioContext

```python
class ScenarioContext:
    """Контекст выполнения сценария"""
    
    user_id: int                    # ID пользователя Telegram
    bot_id: int                     # ID бота
    scenario_id: int                # Текущий сценарий
    variables: Dict[str, Any]       # Переменные диалога
    previous_scenario_id: Optional[int]  # Откуда пришли
    previous_node_id: Optional[str]      # Из какого блока
    nodes_visited: List[str]        # История посещённых блоков
    current_node_id: Optional[str]  # Текущий блок
```

**Файл:** `backend/services/scenario_runtime.py`

---

### Метод execute_go_to_scenario()

```python
def execute_go_to_scenario(
    context: ScenarioContext,
    block_settings: Dict[str, Any],
) -> ScenarioContext:
    """
    Выполнить блок 'go_to_scenario' - переход в другой сценарий.
    
    Args:
        context: Текущий контекст выполнения
        block_settings: Настройки блока:
            - targetScenarioId: ID целевого сценария
            - startMode: 'from_start' или 'from_step'
            - targetNodeId: ID стартового узла (если startMode == 'from_step')
            - preserveContext: сохранять ли переменные (по умолчанию True)
    
    Returns:
        Новый контекст выполнения для целевого сценария
    
    Raises:
        ScenarioRuntimeError: Если целевой сценарий не найден или произошла ошибка
    """
```

**Алгоритм:**

1. **Валидация:**
   - Проверка наличия `targetScenarioId`
   - Проверка существования целевого сценария

2. **Определение стартового узла:**
   - Если `startMode == "from_step"` и указан `targetNodeId`:
     - Использовать указанный блок
   - Иначе:
     - Найти блок "Начало" (блок с `blockId == "start"`)

3. **Сохранение контекста:**
   - Если `preserveContext == true`:
     - Скопировать все переменные из текущего контекста
   - Иначе:
     - Начать с пустыми переменными

4. **Логирование:**
   ```python
   logger.info(
       f"Переход из сценария {context.scenario_id} в сценарий {target_scenario_id} "
       f"(пользователь: {context.user_id}, узел: {start_node.get('id')})"
   )
   ```

5. **Создание нового контекста:**
   ```python
   new_context = ScenarioContext(
       user_id=context.user_id,
       bot_id=context.bot_id,
       scenario_id=target_scenario_id,
       variables=context.variables if preserve_context else {},
       previous_scenario_id=context.scenario_id,
       previous_node_id=context.current_node_id,
   )
   new_context.current_node_id = start_node.get("id")
   ```

6. **Возврат нового контекста**

### Продвинутый тест: переход с конкретного шага

1. Создать сценарий "B" с блоками: "Начало", "Шаг 1", "Шаг 2"
2. В сценарии "A" добавить блок `go_to_scenario`:
   - `targetScenarioId = B`
   - `startMode = "from_step"`
   - `targetNodeId = "Шаг 2"`
   - `preserveContext = true`
3. Запустить сценарий "A"
4. **Ожидание:** переход в "B" сразу на "Шаг 2", контекст сохранён

### Тест: удаление целевого сценария

1. Создать блок `go_to_scenario` с `targetScenarioId = X`
2. Удалить сценарий X
3. Открыть настройки блока
4. **Ожидание:** 
   - Предупреждение "Сценарий не найден"
   - Блок подсвечен как проблемный
   - Валидация показывает ошибку
