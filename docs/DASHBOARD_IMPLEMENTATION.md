## 🔐 RBAC (Role-Based Access Control)

### Роли
- **OWNER** (Владелец проекта) - полный доступ
- **ADMIN** (Администратор) - всё кроме критичных финансовых настроек
- **DEVELOPER** (Разработчик) - боты, шаблоны, аналитика
- **TEMPLATES_MANAGER** (Менеджер шаблонов) - управление шаблонами
- **SUPPORT** (Поддержка) - чтение аналитики и комментариев
- **VIEWER** (Наблюдатель) - только просмотр
- **USER** (Пользователь) - без доступа к ЛК

### Файлы RBAC
- `frontend/src/constants/roles.ts` - конфигурация ролей и прав доступа
- `backend/models/user.py` - список ролей в БД
- `backend/dependencies/roles.py` - проверка прав на backend

### Применение RBAC
Все компоненты ЛК используют:
- `hasAccessToSection()` - проверка доступа к разделам
- `hasAccessToAction()` - проверка прав на действия
- Скрытие/отключение недоступных элементов
- Сообщения об ограничении доступа

- Карточный минимализм
- Фирменные цвета как акцент

- Внутристатичная навигация

## 📝 Критерии приёмки (выполнены)

✅ Глобальная шапка/логотип не изменяются при переходе во все разделы ЛК
✅ Внутренняя боковая панель не выходит за границы контентного контейнера
✅ Пустые состояния корректно рендерятся внутри страниц
✅ RBAC: OWNER видит все разделы; VIEWER ограничен в действиях
✅ Аналитика: смена периода меняет KPI/графики
✅ Платежи: статусы отображаются в карточках
✅ Настройки: локальные изменения не влияют на шапку сайта
