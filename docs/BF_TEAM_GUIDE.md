# Руководство по работе с BF Командой

## Обзор

Вкладка **"BF Команда"** предназначена для управления внутренней командой платформы BotForg. Доступна только владельцу платформы (роль `owner`).

## Основные возможности

### 1. Просмотр участников команды

- **Отображаются все участники BF-команды** (даже если у них нет активных BF-ролей)
- **Сортировка** по любому столбцу (ID, Имя, Email, Базовая роль, BF-роли)
- **Поиск** по email или имени участника
- **Информация о каждом участнике:**
  - ID - 8-значный публичный идентификатор
  - Имя
  - Email
  - Базовая роль (owner, admin, developer, etc.) - отображается на русском языке
  - BF-роли (роли платформы) - может быть пустым

### 2. Добавление участников

**Кнопка: "+ Добавить участника"**

- Введите **8-значный Public ID** пользователя (например: 97410876)
- Выберите **BF-роль** из списка:
  - BF Администратор
  - BF Разработчик
  - BF Менеджер шаблонов
  - BF Поддержка
  - BF Аналитик
  - BF Модератор
- *Опционально:* Укажите срок действия роли (в днях)

**Как узнать Public ID пользователя:**
- Пользователь может посмотреть свой ID в личном кабинете (Dashboard, сайдбар)
- ID отображается под именем пользователя

### 3. Управление ролями участников

**Настройка ролей (кнопка "Настройка" ⚙️):**
- Открывает модальное окно с настройками участника
- **Базовая роль в проекте** - можно изменить базовую роль (owner, admin, developer, etc.)
- **BF-роли платформы** - можно добавить новую BF-роль
- Изменения сохраняются автоматически

**Добавление BF-роли:**
- Кнопка **"Настройка"** (⚙️) рядом с каждым участником
- В модальном окне выберите BF-роль из списка
- Можно назначить несколько BF-ролей одному участнику
- Можно указать срок действия роли (в днях)

**Удаление конкретной BF-роли:**
- Нажмите **крестик (X)** на плашке роли в таблице
- Роль будет удалена после подтверждения
- ⚠️ **Важно:** Участник остается в списке даже после удаления всех ролей

### 4. Удаление участника из команды

**Кнопка корзины (🗑️) в колонке "Действия":**
- **Всегда активна** - доступна для всех участников команды, независимо от наличия BF-ролей
- При удалении:
  - **Все BF-роли участника удаляются**
  - **Участник удаляется из списка команды**
  - **Базовая роль автоматически меняется на "user"** (ограничивает доступ к платформе)
  - Пользователь остается в системе, но без доступа к dashboard

## Публичные ID (Public ID)

### Что это?

- **8-значный случайный номер** (например: 97410876)
- Уникальный для каждого пользователя
- Не позволяет узнать количество пользователей платформы
- Невозможно подобрать или угадать

### Где отображается?

1. **В сайдбаре Dashboard** - под именем пользователя
2. **В таблице BF Команда** - колонка "ID"
3. **В модальных окнах** - при работе с участниками

### Использование

- При добавлении участника в команду используйте **Public ID** (8 цифр)
- Система автоматически найдет пользователя по Public ID
- Для обратной совместимости поддерживается и внутренний ID

## Безопасность

### Права доступа

- ✅ **Owner (Владелец платформы)** - полный доступ к BF Команде
- ❌ **Все остальные роли** - вкладка не отображается

### Защиты

- Нельзя удалить себя из команды
- Нельзя понизить собственную роль владельца
- Проверка валидности BF-ролей
- Защита от дублирования активных ролей

## Техническая информация

### Архитектура

- **Backend:** FastAPI, SQLAlchemy
- **Frontend:** React, TypeScript
- **База данных:** SQLite (в production рекомендуется PostgreSQL)

### API Endpoints

- `GET /api/platform-admin/users?team_only=true` - список участников команды
- `POST /api/platform-admin/roles` - назначить BF-роль (автоматически добавляет в команду)
- `PATCH /api/platform-admin/roles/{role_id}` - обновить BF-роль
- `DELETE /api/platform-admin/roles/{role_id}` - удалить конкретную BF-роль
- `PATCH /api/platform-admin/users/{user_id}/base-role?role=...` - изменить базовую роль
- `DELETE /api/platform-admin/users/{user_id}/team-member` - удалить участника из команды

### Модели данных

**User:**
- `id` - внутренний ID (INTEGER)
- `public_id` - публичный 8-значный ID (BIGINT)
- `email`, `name`, `role`, etc.

**PlatformRole:**
- `id`, `user_id`, `role_name`
- `granted_by`, `granted_at`, `expires_at`
- `is_active`, `notes`

**BFTeamMember:**
- `id`, `user_id`, `added_by`
- `added_at`, `is_active`
- Отслеживает участников команды отдельно от ролей
- Участники остаются в списке даже после удаления всех ролей

## Изменения в архитектуре

### Удалена страница /account

- Страница `/account` была дублированием функционала Dashboard
- Все редиректы теперь ведут на `/dashboard`
- Единая точка входа в личный кабинет

### Добавлен Public ID

- Поле `public_id` в модели User
- 8-значный случайный номер для каждого пользователя
- Отображается в UI вместо внутреннего ID
- Используется для добавления участников в команду

## Важные изменения

### Система отслеживания участников команды

**Проблема:** Раньше участники исчезали из списка после удаления всех BF-ролей, но сохраняли базовую роль и могли использовать платформу бесплатно.

**Решение:** Создана отдельная таблица `bf_team_members` для отслеживания участников команды:
- Участники остаются в списке даже после удаления всех BF-ролей
- Удаление из команды происходит только через кнопку "Удалить участника"
- При удалении участника базовая роль автоматически меняется на `user` (ограничивает доступ)

### Сортировка и фильтрация

- Добавлена сортировка по всем столбцам таблицы
- Трехпозиционное переключение: по возрастанию → по убыванию → без сортировки
- Визуальные индикаторы направления сортировки (стрелки)

### Улучшения UI/UX

- Кнопка "Роль" заменена на "Настройка" (⚙️) с расширенным функционалом
- Все базовые роли отображаются на русском языке
- Toast-уведомления вместо alert
- Автоматическое закрытие модальных окон после успешного сохранения
