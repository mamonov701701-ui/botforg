# 🎯 Иерархия ролей BotForg

## 📊 Общая структура

В платформе BotForg существует **три уровня ролей**, которые работают независимо друг от друга:

```
┌─────────────────────────────────────────────────────────────┐
│                    УРОВЕНЬ 1: БАЗОВЫЕ РОЛИ                  │
│              (определяют доступ к платформе)                │
│                                                              │
│  owner → admin → developer → templates_manager → support →  │
│  viewer → user                                               │
│                                                              │
│  Хранится в: users.role + base_roles (история)             │
│  Назначается: Владельцем через "BF Команда"                 │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                    УРОВЕНЬ 2: BF-РОЛИ                       │
│        (идентификация участников команды платформы)         │
│                                                              │
│  BF Администратор → BF Разработчик → BF Менеджер шаблонов → │
│  BF Поддержка → BF Аналитик → BF Модератор                  │
│                                                              │
│  Хранится в: platform_roles                                 │
│  Назначается: Владельцем через "BF Команда"                  │
│  Особенность: НЕ дают доступа, только идентификация         │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│              УРОВЕНЬ 3: РОЛИ КОМАНДЫ ПРОЕКТА                 │
│         (роли в конкретном проекте владельца)                │
│                                                              │
│  admin → developer → templates_manager → support → viewer    │
│                                                              │
│  Хранится в: team_members.role + base_roles (история)      │
│  Назначается: Владельцем через "Команда"                    │
│  Особенность: Работает только в рамках проекта владельца    │
└─────────────────────────────────────────────────────────────┘
```

---

## 🔍 Детальное описание уровней

### УРОВЕНЬ 1: Базовые роли (Base Roles)

**Назначение:** Определяют **фактический доступ** пользователя к разделам и функциям платформы.

**Где хранится:**
- `users.role` - текущая активная роль
- `base_roles` - история всех назначенных базовых ролей с датами и сроками

**Иерархия доступа (от большего к меньшему):**

```
1. owner (Владелец проекта)
   ├─ Полный доступ ко всем разделам
   ├─ Управление BF-командой
   └─ Управление командой проекта

2. admin (Администратор)
   ├─ Почти полный доступ
   ├─ Управление командой проекта
   └─ НЕТ доступа к BF-команде

3. developer (Разработчик)
   ├─ Боты и шаблоны
   ├─ Аналитика
   └─ НЕТ доступа к балансу и команде

4. templates_manager (Менеджер шаблонов)
   ├─ Шаблоны (с публикацией)
   ├─ Аналитика
   └─ НЕТ доступа к ботам

5. support (Поддержка)
   ├─ Только просмотр аналитики
   └─ НЕТ прав на изменения

6. viewer (Наблюдатель)
   ├─ Только просмотр
   └─ НЕТ прав на изменения

7. user (Пользователь)
   └─ НЕТ доступа к dashboard
```

**Особенности:**
- ✅ Определяют доступ к разделам
- ✅ Могут иметь срок действия (временные роли)
- ✅ История хранится в `base_roles`
- ✅ При удалении из команды проекта автоматически меняется на `user`

---

### УРОВЕНЬ 2: BF-роли (Platform Roles)

**Назначение:** Идентификация участников **внутренней команды платформы BotForg**.

**Где хранится:**
- `platform_roles` - таблица с BF-ролями

**Важно:**
- ❌ **НЕ определяют доступ** к разделам и функциям
- ✅ Только **идентификация** и **метки** для участников команды
- ✅ Можно иметь **несколько BF-ролей** одновременно
- ✅ Могут иметь **срок действия**

**Доступные BF-роли:**
```
- BF Администратор
- BF Разработчик
- BF Менеджер шаблонов
- BF Поддержка
- BF Аналитик
- BF Модератор
```

**Пример использования:**
```
Пользователь: Иван
├─ Базовая роль: developer (дает доступ к ботам)
└─ BF-роль: BF Разработчик (идентифицирует как разработчика команды)

Результат: 
- Иван имеет доступ к ботам (из базовой роли)
- Иван отображается как "BF Разработчик" в списке команды
```

---

### УРОВЕНЬ 3: Роли команды проекта (Team Roles)

**Назначение:** Роли участников в **конкретном проекте** владельца.

**Где хранится:**
- `team_members.role` - роль в проекте
- `base_roles` - история базовых ролей для этого проекта

**Особенности:**
- ✅ Работает только в рамках **одного проекта** владельца
- ✅ Каждый владелец может иметь свою команду проекта
- ✅ Участник может быть в командах разных владельцев с разными ролями
- ✅ При удалении из команды проекта базовая роль меняется на `user`

**Доступные роли команды:**
```
- admin (Администратор проекта)
- developer (Разработчик проекта)
- templates_manager (Менеджер шаблонов проекта)
- support (Поддержка проекта)
- viewer (Наблюдатель проекта)
```

**Пример:**
```
Владелец проекта: Виктор (owner)

Команда проекта Виктора:
├─ Иван (developer) - разработчик в проекте Виктора
├─ Мария (templates_manager) - менеджер шаблонов в проекте Виктора
└─ Петр (support) - поддержка в проекте Виктора

Каждый участник имеет:
- Роль в проекте Виктора (team_members.role)
- Базовую роль для доступа к платформе (base_roles)
```

## 🔄 Как работают роли вместе

### Пример 1: Владелец платформы

```
Пользователь: Виктор
├─ Базовая роль: owner
│  └─ Доступ: ВСЁ (включая BF Команду)
├─ BF-роль: BF Администратор
│  └─ Идентификация: Администратор команды платформы
└─ Роль в проекте: owner (сам себе)
   └─ Управляет своей командой проекта
```

### Пример 2: Разработчик команды платформы

```
Пользователь: Иван
├─ Базовая роль: developer
│  └─ Доступ: Боты, Шаблоны, Аналитика
├─ BF-роль: BF Разработчик
│  └─ Идентификация: Разработчик команды платформы
└─ Роль в проекте: developer (в проекте Виктора)
   └─ Работает над проектом Виктора
```

### Пример 3: Внешний разработчик (не в BF-команде)

```
Пользователь: Петр
├─ Базовая роль: developer
│  └─ Доступ: Боты, Шаблоны, Аналитика
├─ BF-роль: НЕТ
│  └─ Не является частью команды платформы
└─ Роль в проекте: developer (в проекте Виктора)
   └─ Работает над проектом Виктора, но не в команде платформы
```

## 📍 Где назначаются роли

### Базовые роли:
- **Раздел:** "BF Команда" → "Настройка" → вкладка "Базовая роль в проекте"
- **Кто может:** Только владелец (owner)
- **Что делает:** Определяет доступ к платформе

### BF-роли:
- **Раздел:** "BF Команда" → "Настройка" → вкладка "BF-роли"
- **Кто может:** Только владелец (owner)
- **Что делает:** Идентифицирует участников команды платформы

### Роли команды проекта:
- **Раздел:** "Команда" → "Настройка"
- **Кто может:** Только владелец проекта (owner)
- **Что делает:** Определяет роль в конкретном проекте

## 🎯 Быстрая справка

| Вопрос | Ответ |
|--------|-------|
| **Что определяет доступ к разделам?** | Базовая роль (users.role) |
| **Что такое BF-роли?** | Метки для идентификации участников команды платформы |
| **Можно ли иметь несколько BF-ролей?** | Да |
| **Можно ли иметь несколько базовых ролей?** | Нет, только одна активная |
| **Где хранится история базовых ролей?** | Таблица `base_roles` |
| **Что происходит при удалении из команды проекта?** | Базовая роль меняется на `user` |
| **Что происходит при удалении из BF-команды?** | BF-роли удаляются, базовая роль сохраняется |
| **Кто может назначать роли?** | Только владелец (owner) |

## 💡 Рекомендации

### Для владельца платформы:

1. **Базовая роль `owner`** должна быть только у вас
2. **BF-роли** используйте для идентификации участников команды платформы
3. **Роли команды проекта** используйте для управления участниками вашего проекта
4. Всегда проверяйте активную базовую роль для определения доступа

### Типичные комбинации:

**Внутренний разработчик команды:**
- Базовая роль: `developer`
- BF-роль: `BF Разработчик`
- Роль в проекте: `developer`

**Внешний разработчик:**
- Базовая роль: `developer`
- BF-роль: нет
- Роль в проекте: `developer`

**Администратор платформы:**
- Базовая роль: `admin`
- BF-роль: `BF Администратор`
- Роль в проекте: `admin`

---

## 🔐 Доступ к ботам владельца

**Важно:** Участники команды проекта **НЕ имеют автоматического доступа** к ботам владельца.

### Как это работает:

- ✅ Разработчик с ролью `developer` может создавать **свои собственные боты**
- ✅ Разработчик видит и редактирует **только свои боты**
- ❌ Разработчик **НЕ видит** боты владельца проекта
- ❌ Разработчик **НЕ может** редактировать боты владельца проекта
