# Версионирование сценариев

## Обзор

Сценарии имеют два режима:
- **draft (черновик)** — рабочая копия, автосохранение, версионирование (см. [editor_autosave.md](./editor_autosave.md));
- **published (опубликовано)** — версия, которую использует бот.

При каждом сохранении черновика создаётся запись в `scenario_versions` (version_type=draft). Это позволяет:
- просматривать историю изменений;
- восстанавливать предыдущие версии черновика.

## Модель данных

### Scenario

| Поле             | Тип      | Описание                                      |
|------------------|----------|-----------------------------------------------|
| content          | JSON     | Черновик (nodes, edges)                       |
| published_content| JSON     | Опубликованная версия (используется ботом)   |
| status           | enum     | draft \| published                            |

Новые сценарии создаются со статусом `draft`. Бот использует только сценарии со статусом `published` и полем `published_content`.

### ScenarioVersion

| Поле        | Тип      | Описание                                      |
|-------------|----------|-----------------------------------------------|
| id          | int      | Первичный ключ                                |
| scenario_id | int      | ID сценария                                   |
| version     | int      | Порядковый номер версии (1, 2, 3...)          |
| version_type| enum     | draft \| published                            |
| content     | JSON     | Снимок nodes и edges                          |
| is_active   | bool     | Текущая активная версия (по типу)             |
| created_at  | datetime | Время создания версии                         |

## API

### POST /scenarios/{scenario_id}/publish

Опубликовать черновик сценария.

**Логика:**
1. Копирует `content` (черновик) в `published_content`.
2. Устанавливает `status=published`.
3. Создаёт версию с `version_type=published`.
4. Предыдущая published-версия помечается `is_active=false`.

**Права доступа:** владелец или участник с правом редактирования (owner, admin, developer, user).

**Ответ:** обновлённый сценарий (ScenarioOut).

### GET /scenarios/{scenario_id}/versions

Возвращает список версий черновика (version_type=draft), отсортированный по номеру версии (новые первыми).

**Права доступа:** владелец сценария или участник команды с доступом к боту.

**Ответ:**
```json
[
  {
    "id": 5,
    "version": 3,
    "created_at": "2026-02-02T14:30:00.000Z",
    "is_active": true
  },
  {
    "id": 4,
    "version": 2,
    "created_at": "2026-02-02T12:00:00.000Z",
    "is_active": false
  },
  {
    "id": 3,
    "version": 1,
    "created_at": "2026-02-02T10:00:00.000Z",
    "is_active": false
  }
]
```

### POST /api/scenarios/{scenario_id}/restore/{version_id}

Восстанавливает сценарий из выбранной версии.

**Логика:**
1. Копирует `content` из указанной версии в `scenario.content` (черновик).
2. Снимает флаг `is_active` с текущей активной draft-версии.
3. Создаёт новую draft-версию с восстановленным content.

**Права доступа:** владелец сценария или участник команды с правом редактирования (owner, admin, developer).

**Ответ:** обновлённый сценарий (ScenarioOut).

**Ошибки:**
- 404 — сценарий или версия не найдены.
- 403 — нет прав на восстановление.
- 400 — версия не содержит данных.

## Пример сценария отката

### 1. Получить историю версий

```bash
curl -X GET "https://api.example.com/api/scenarios/42/versions" \
  -H "Authorization: Bearer <token>"
```

### 2. Восстановить предыдущую версию

```bash
curl -X POST "https://api.example.com/api/scenarios/42/restore/4" \
  -H "Authorization: Bearer <token>"
```

После восстановления:
- сценарий содержит nodes/edges из версии 4;
- создана новая версия (например, version=4), фиксирующая факт отката;
- предыдущая активная версия помечена как `is_active=false`.

### 3. Проверка в редакторе

После успешного restore фронтенд должен перезагрузить сценарий (например, через `loadBotScenarios` или `selectScenario`), чтобы отобразить восстановленное состояние.

## Транзакционность

Операция восстановления выполняется в одной транзакции:
- обновление `scenario.content`;
- снятие `is_active` с предыдущей версии;
- создание новой версии.

При ошибке все изменения откатываются.

## Создание версий

**Draft-версии** создаются при:
1. **Создании сценария** — если передан `content`.
2. **Обновлении сценария** — при изменении поля `content` (PUT /scenarios/{id}).
3. **Восстановлении** — при restore из истории.

**Published-версии** создаются при вызове POST /scenarios/{id}/publish.

При обновлении других полей (name, description и т.д.) без изменения content новая версия не создаётся.

## Автосохранение

Обновления контента в редакторе сохраняются только в черновик (`content`). Продакшн-сценарий (`published_content`) не меняется до явной публикации.
