# DEV CHECKLIST — локальный запуск BotForg

Этот чек-лист нужен, чтобы быстро проверить, что локальная разработка работает end-to-end.

## 1. Порты (единый источник правды)

- **Frontend (Vite)**: `http://localhost:5173`
- **Backend (FastAPI / uvicorn)**: `http://localhost:8001`

Подробнее см. `docs/DEV_PORTS.md`.

## 2. Запуск проекта

Рекомендуемый способ (полный стек, одна команда из корня проекта):

```powershell
cd C:\Users\mamon\botforg
npm run dev
```

(то же самое: `.\scripts\start-dev.ps1`.)

Только backend (канон для локальной разработки API / «перезапусти :8001»):

```powershell
cd C:\Users\mamon\botforg
.\scripts\dev-backend.ps1
```

- venv: `backend\venv\Scripts\python.exe`
- `127.0.0.1:8001` + `--reload`
- fail closed, если порт занят неизвестным процессом

Что делает `start-dev.ps1`:

- освобождает порты `8001`, `5173`, `5174`;
- применяет миграции (`alembic upgrade head` из корня);
- поднимает backend и frontend в фоне (логи в `scripts/.dev-*-*.log`);
- проверяет `/healthz`, ответ фронта и пробу `POST /auth/email/login` (ожидается 401 или 422).

Не используйте произвольный `uvicorn ...` для обычной локальной разработки.
## 3. Проверка backend

1. Убедиться, что процесс uvicorn слушает порт:

```powershell
netstat -ano | findstr 8001
```

Должна быть строка с `LISTENING` на `0.0.0.0:8001`.

2. Проверить health:

```powershell
curl http://localhost:8001/healthz
```

Ожидаемый ответ:

```json
{"status": "ok"}
```

3. Проверить Swagger:

- Открыть в браузере: `http://localhost:8001/docs`

## 4. Проверка frontend

1. Открыть в браузере:

- `http://localhost:5173`

2. Убедиться, что в консоли браузера **нет**:

- `ERR_CONNECTION_REFUSED` для `/auth/...` или `/api/...`;
- бесконечных ошибок `failed to connect to websocket` от Vite.

## 5. Проверка логина

1. Использовать тестового владельца:

- email: `mamonov701701@mail.ru`
- password: `Test123456!`

2. На фронте:

- открыть страницу логина;
- выполнить вход указанными данными;
- убедиться, что после логина открывается личный кабинет (dashboard), а не ошибка сети.

3. В Network (devtools):

- запрос `POST /auth/email/login`:
  - статус **200** (или ожидаемая бизнес-ошибка),
  - **НЕ** `ERR_CONNECTION_REFUSED`;
  - запрос идёт на `http://localhost:5173/auth/email/login` и проксируется на `http://localhost:8001/auth/email/login`.

## 6. Проверка редактора

1. Открыть редактор:

- из шапки сайта кнопка **«Редактор»** → маршрут `/editor`;
- система автоматически:
  - подбирает существующий бот и его основной/последний сценарий и открывает `/editor/{botId}`, **или**
  - при первом запуске переадресует в раздел “Мои боты” для создания первого бота.
2. Убедиться, что:

- редактор открывается (без пустого экрана);
- в консоли **нет** ошибок `Maximum update depth exceeded`.

3. Проверить функции:

- **загрузка сценариев** — выпадающий список сценариев заполняется;
- **импорт JSON** — файл вида `{ "nodes": [...], "edges": [...] }` импортируется через кнопку «Импорт», граф появляется на канвасе;
- **предпросмотр** — кнопка «Предпросмотр» открывает симулятор, диалог корректно проигрывается;
- **публикация** — для валидного черновика кнопка «Опубликовать» активна и после подтверждения сценарий получает статус «Опубликовано»;
- **обновление публикации** — для опубликованного сценария с изменениями кнопка меняет подпись на «Обновить публикацию» и успешно обновляет опубликованную версию;
- **автосохранение** — при правках в редакторе через несколько секунд статус автосохранения меняется на «Сохранено», без ошибок в консоли;
- **проверка сценария** — кнопка открывает модалку «Проверка сценария»: ошибки схемы блоков и консистентности на русском; при недоступности API определений переменных (`/bots/{id}/variable-definitions`) редактор не должен «падать» — граф остаётся доступным.

Разработчикам: архитектура валидации и guard’ы store описаны в `docs/development/EDITOR_VALIDATION_AND_DIAGNOSTICS.md`. Регрессии: `frontend/tests/unit/validationStoresStability.test.ts`.

## 7. Мониторинг консоли (браузер)

Во время работы редактора/чата в консоли **не должно** быть:

- `Maximum update depth exceeded`;
- непрерывных ошибок WebSocket от Vite (`failed to connect to websocket`);
- лавины запросов к `/chat/unread-count` (должен быть опрос примерно раз в 30 секунд, пока пользователь залогинен).

Если какой-либо из этих пунктов нарушен, сначала проверьте:

- что backend реально запущен на `8001`;
- что frontend (Vite) запущен на `5173`;
- что конфиги соответствуют `docs/DEV_PORTS.md`.
