# 🛡️ Руководство по управлению платформой (Platform Admin)

## Обзор

Platform Admin - это комплексная система управления платформой BotForg, доступная исключительно владельцам платформы (роль `bf_owner`). Предоставляет инструменты для мониторинга, модерации и управления всеми пользователями и ресурсами.

## 🎯 Доступ

**Требования:**
- Роль: `bf_owner` (владелец платформы)
- Навигация: Dashboard → раздел "Платформа"

**Подразделы:**
1. **Обзор** - ключевые метрики и KPI платформы
2. **Пользователи** - управление пользователями и их ресурсами
3. **Аналитика** - маркетинговая аналитика всей платформы

## 📊 1. Обзор платформы

### Ключевые показатели (KPI)

Страница обзора отображает 7 основных метрик:

1. **Всего пользователей**
   - Общее количество зарегистрированных пользователей
   - Включает все роли (от user до bf_owner)

2. **Всего проектов**
   - Количество уникальных владельцев ботов
   - Пользователь с ботами = проект

3. **Всего ботов**
   - Общее количество созданных ботов
   - Включает активные и неактивные

4. **Активных ботов**
   - Боты со статусом `is_active = true`
   - Работающие и принимающие сообщения

5. **Всего сценариев**
   - Количество созданных сценариев
   - Включая библиотечные и приватные

6. **Пользователей ботов**
   - Уникальные пользователи Telegram, взаимодействовавшие с ботами
   - Подсчитываются по `telegram_user_id`

7. **Всего сообщений**
   - Общее количество обработанных сообщений
   - Входящие + исходящие

### Визуализация

- **Карточки KPI** с иконками и градиентным фоном
- **Цветовая кодировка:**
  - 🟢 Зеленый - активность, пользователи ботов
  - 🔵 Синий - пользователи, проекты
  - 🟡 Желтый - боты
  - 🟣 Фиолетовый - сценарии
  - 🟠 Оранжевый - сообщения

### Обновление данных

- Данные загружаются при открытии страницы
- Кнопка "Обновить" для принудительной перезагрузки
- API endpoint: `GET /api/platform-admin/stats`

## 👥 2. Управление пользователями

### Список пользователей

**Возможности:**
- Просмотр всех зарегистрированных пользователей
- Поиск по имени, email, public_id
- Фильтрация по ролям
- Пагинация (10, 25, 50, 100 записей на страницу)

**Отображаемые поля:**
- ID пользователя
- Имя и Public ID
- Email
- Роль (user, manager, analyst, support, admin, owner)
- Платформенные роли BF (если есть)
- Дата регистрации

### Детальная информация о пользователе

При клике на пользователя открывается страница с полной информацией:

#### Основная информация
- ID, Public ID
- Имя и Email
- Роль и платформенные роли
- Дата регистрации

#### Статус блокировки

**Типы блокировки:**
1. **Предупреждение** (`warning`)
   - Видимое предупреждение пользователю
   - Не блокирует доступ
   - Используется для первичной модерации

2. **Временная блокировка** (`temporary`)
   - Блокировка на определенный срок
   - Требует указания даты окончания
   - Автоматическая разблокировка после срока

3. **Постоянная блокировка** (`permanent`)
   - Бессрочная блокировка
   - Требует указания причины
   - Разблокировка только вручную

**Отображение статуса:**
- 🟢 Зеленая карточка - активен
- 🟡 Желтая карточка - предупреждение
- 🔴 Красная карточка - заблокирован

**Информация о блокировке:**
- Тип блокировки
- Причина
- Дата блокировки
- Дата окончания (для временной)
- ID администратора, выдавшего блокировку

#### Действия с пользователем

**Кнопки управления:**
- **Приостановить пользователя** - открывает модальное окно блокировки
- **Разблокировать пользователя** - снимает любую блокировку
- **Приостановить все боты** - массовая блокировка всех ботов пользователя
- **Разблокировать все боты** - массовая разблокировка

#### Ресурсы пользователя

**Вкладка "Боты":**
- Список всех ботов пользователя
- Для каждого бота:
  - Название и описание
  - Статус (активен/неактивен)
  - Статус блокировки (если есть)
  - Кнопки "Приостановить" / "Разблокировать"
  - Ссылка на редактор бота

**Вкладка "Сценарии":**
- Список всех сценариев
- Название, описание, категория
- Привязка к боту (если есть)
- Статус библиотеки

**Вкладка "Активность":**
- История последних действий пользователя
- (В разработке)

### Модальное окно блокировки

**Поля:**
1. **Тип блокировки** (radio buttons)
   - Предупреждение
   - Временная блокировка
   - Постоянная блокировка

2. **Причина** (textarea, обязательное)
   - Описание нарушения
   - Будет видно пользователю

3. **Длительность** (только для временной)
   - 1 день
   - 3 дня
   - 7 дней
   - 14 дней
   - 30 дней
   - Свой срок (ручной ввод даты)

**Подтверждение:**
- Кнопка "Приостановить" применяет блокировку
- Отмена закрывает модальное окно без изменений

## 🔒 3. Система блокировок

### Блокировка пользователя

**Эффект:**
- Пользователь не может войти в систему
- Все боты пользователя продолжают работать (если не заблокированы отдельно)
- При попытке входа отображается причина блокировки

**API:** `POST /api/platform-admin/users/{user_id}/suspend`

**Тело запроса:**
```json
{
  "suspension_type": "temporary",
  "reason": "Нарушение правил платформы",
  "suspended_until": "2026-02-20T00:00:00Z"
}
```

### Блокировка бота

**Эффект:**
- Бот перестает обрабатывать сообщения
- В БД выставляется флаг `is_suspended = true`
- Пользователи Telegram видят, что бот не отвечает

**API:** `POST /api/platform-admin/bots/{bot_id}/suspend`

**Применение:**
- Блокировка спам-ботов
- Модерация контента
- Нарушение ToS

### Массовая блокировка ботов

**Использование:**
- Когда пользователь нарушает правила платформы
- Нужно остановить все его боты одновременно

**API:** `POST /api/platform-admin/users/{user_id}/suspend-all-bots`

**Отличие от блокировки пользователя:**
- Пользователь может войти в систему
- Но не может запустить свои боты
- Может создать новых ботов (которые будут работать, если не заблокированы)

### Разблокировка

**Пользователь:**
- `POST /api/platform-admin/users/{user_id}/unsuspend`
- Снимает все ограничения
- Удаляет причину и тип блокировки

**Бот:**
- `POST /api/platform-admin/bots/{bot_id}/unsuspend`
- Бот снова начинает работать

**Все боты:**
- `POST /api/platform-admin/users/{user_id}/unsuspend-all-bots`
- Разблокирует все боты пользователя разом

## 📈 4. Аналитика платформы

(Доступна в разделе "Платформа" → "Аналитика")

Предоставляет те же возможности, что и обычная аналитика, но для всех ботов платформы:
- Фильтрация по конкретному боту
- Просмотр активности всех пользователей
- Маркетинговые метрики
- Экспорт данных

См. [Marketing Analytics Guide](./MARKETING_ANALYTICS_GUIDE.md) для подробностей.

## 🛠️ Практические сценарии

### Сценарий 1: Модерация спам-бота

**Проблема:** Пользователь создал бота, который спамит

**Решение:**
1. Перейдите в "Платформа" → "Пользователи"
2. Найдите пользователя по имени или email
3. Откройте детальную информацию
4. Во вкладке "Боты" найдите спам-бота
5. Нажмите "Приостановить" для конкретного бота
6. Укажите причину: "Спам, нарушение правил"
7. Тип: "Постоянная блокировка"
8. Подтвердите

**Результат:** Бот перестает работать, остальные боты пользователя продолжают функционировать.

### Сценарий 2: Предупреждение пользователю

**Проблема:** Пользователь нарушил правила, но некритично

**Решение:**
1. Откройте детальную информацию пользователя
2. Нажмите "Приостановить пользователя"
3. Выберите тип: "Предупреждение"
4. Укажите причину: "Некорректный контент в описании бота"
5. Подтвердите

**Результат:** Пользователь видит предупреждение, но сохраняет полный доступ к платформе.

### Сценарий 3: Временная блокировка за нарушение

**Проблема:** Пользователь неоднократно нарушал правила

**Решение:**
1. Откройте детальную информацию пользователя
2. Нажмите "Приостановить пользователя"
3. Выберите тип: "Временная блокировка"
4. Длительность: "7 дней"
5. Причина: "Повторное нарушение правил платформы"
6. Подтвердите

**Результат:** Пользователь не может войти 7 дней, после чего блокировка снимается автоматически.

### Сценарий 4: Массовая блокировка всех ботов

**Проблема:** Пользователь использует ботов для мошенничества

**Решение:**
1. Откройте детальную информацию пользователя
2. Нажмите "Приостановить все боты"
3. Укажите причину
4. Подтвердите

**Дополнительно:**
5. Нажмите "Приостановить пользователя"
6. Тип: "Постоянная блокировка"
7. Причина: "Мошенничество"

**Результат:** Все боты заблокированы, пользователь не может войти в систему.

### Сценарий 5: Разблокировка после апелляции

**Проблема:** Пользователь исправился и просит разблокировать

**Решение:**
1. Откройте детальную информацию пользователя
2. Проверьте причину блокировки и историю
3. Нажмите "Разблокировать пользователя"
4. Если были заблокированы боты, нажмите "Разблокировать все боты"

**Результат:** Полный доступ восстановлен.

## 🔐 Безопасность

### Логирование действий

Все действия владельца платформы логируются:
- Блокировка/разблокировка пользователей
- Блокировка/разблокировка ботов
- Просмотр детальной информации
- Экспорт данных

### Права доступа

**Только bf_owner:**
- Доступ к разделу "Платформа"
- Просмотр всех пользователей
- Блокировка пользователей и ботов
- Просмотр аналитики всей платформы

**Другие роли:**
- Не видят раздел "Платформа" в навигации
- API возвращает 403 Forbidden при попытке доступа

### Защита от ошибок

- Подтверждение перед блокировкой
- Обязательное указание причины
- Невозможность заблокировать самого себя (владельца)

## 🆘 Решение проблем

**Проблема:** Не могу найти пользователя в списке
- **Решение:** Используйте поиск по email или имени. Проверьте правильность написания.

**Проблема:** После блокировки бот продолжает работать
- **Решение:** Убедитесь, что блокировали именно бота, а не пользователя. Блокировка пользователя не блокирует его ботов автоматически.

**Проблема:** Не могу разблокировать пользователя
- **Решение:** Проверьте логи на наличие ошибок. Возможно, есть проблемы с БД. Обратитесь к системному администратору.

**Проблема:** KPI показывают нули
- **Решение:** Проверьте подключение к БД. Возможно, данные еще не загружены. Нажмите кнопку "Обновить".
